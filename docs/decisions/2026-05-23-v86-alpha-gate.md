# 2026-05-23 v8.6 — Alpha Gate 自动暂停（P1-3）

## 问题

`etf_gate.py` 已存在，能把"系统跑赢/跑输沪深 300"分类为 severe / warning / normal / stale。但是被动的——只在 Bark 推送顶部加横幅。用户可以一直忽略横幅继续磨损资金。

实际数据：当前 honest_evaluation.md 显示 excess=-6.02%（severe），但系统继续每天选股推送。

## 决策

新增 `alpha_gate.py` —— 主动 fail-safe：

- 每天调用 `evaluate_etf_gate()` 拿 severity
- severity=severe → 计数器 +1
- severity ∈ (normal, warning) → 计数器归零
- severity ∈ (unknown, stale) → 计数器不变（不能因数据缺失误判）
- 计数器 ≥ `lookback_days`（默认 5）→ paused=True
- 一旦暂停：每天还会继续 check + 记历史，但 paused 不会自动恢复
- 用户重启：`python alpha_gate.py --reset`
- 触发暂停的当次 check 发独立 Bark 通知（pause_triggered_now=True）

## 风险

- 当前真实数据已经 severe（excess=-6.02%），所以本周内每天跑 daily_pipeline 会让计数器累加，5 天后系统会自动暂停。**这是设计意图** — 用户应该看到 Bark 暂停通知后，要么手动 reset 要么转去买 ETF。
- alpha_gate.enabled=True 是默认开启。如果用户测试期想关闭，改 `data/system_config.json` 加 `"alpha_gate": {"enabled": false}` 即可。
- `is_paused()` 在 state file 损坏时返回 `(False, "")` — 不暂停（fail-open）。这是有意为之：状态文件读不出来时优先保证 pipeline 能跑，而不是因损坏文件锁死。

## 触发后用户操作流程

1. Bark 收到推送：`[Alpha Gate] 系统已暂停 ... 连续 5 天跑输沪深300（latest -X.XX%）...`
2. 决定：
   - 接受暂停建议 → 转去买 ETF（510300/510310），系统就让它停着
   - 不接受 → 跑 `python alpha_gate.py --reset` 恢复，下次 daily_pipeline 正常运行
3. 注意：reset 只清 paused 标志和 counter，**不删 history**（history 是审计依据）
